# cod-report

Vue 3/Vite 보고서 편집기와 Node.js 기반 API입니다. 보고서를 저장하고, MySQL/MariaDB의 조회 결과를 요소에 연결할 수 있습니다.

## Docker로 MariaDB와 서버 함께 실행

1. Docker Desktop을 설치하고 실행합니다.
2. `.env.example`을 `.env`로 복사한 뒤 `DB_PASSWORD`와 `DB_ROOT_PASSWORD`를 서로 다른 강력한 비밀번호로 변경합니다.
3. `npm run db:up`으로 MariaDB와 API/웹 서버를 빌드하고 시작합니다.
4. `http://localhost:19080`에 접속해 최초 관리자 계정을 만든 뒤 로그인하고 에디터 또는 뷰어를 선택합니다.

로그인 후 `/`는 도구 선택 메인 화면입니다. 에디터, 뷰어, 사용자·그룹 관리와 메인 화면에서 로그아웃할 수 있으며, 로그인 상태에서 `/login`으로 돌아가도 메인 화면이 표시됩니다. 에디터 또는 뷰어에서 저장하지 않은 작업이 있는 경우 로그아웃 전에 확인합니다.

로그인 후 도구 선택 화면의 제목 옆, 에디터, 뷰어 및 사용자·그룹 관리 화면의 **도움말**에서 대분류 → 기능 분류 → 세부 기능의 3단계 목차와 검색을 사용할 수 있습니다. 기능별 절차와 설정 항목, 제약 사항을 풀 HD 예시 화면과 함께 안내하며 빨간 박스로 관련 기능을 표시합니다. 이미지 크게 보기를 누르면 원본을 볼 수 있습니다. 설명서 화면은 예시이며 역할과 설정에 따라 실제 화면이 다를 수 있습니다.

MariaDB는 `cod_report` 데이터베이스를 생성하고, API는 첫 요청 시 보고서·일정·데이터소스 및 로그인·사용자·그룹·세션·양식 열람 권한 테이블을 자동 생성합니다. 비밀번호는 scrypt 해시로 저장되고, 브라우저 세션은 12시간짜리 HttpOnly 쿠키로 유지됩니다. 최초 설정 화면에서 생성하는 계정은 관리자입니다. 5회 연속 로그인 실패 시 계정이 잠기며, 관리자가 사용자 설정에서 잠금 해제를 할 수 있습니다. 역할은 관리자(사용자·그룹·접속정보 관리 포함), 에디터(양식 편집), 뷰어(허용된 결과 열람)입니다.

관리자는 `/admin`(로그인 후 도구 선택 화면의 **사용자·그룹 관리**) 또는 뷰어·에디터 상단의 **사용자·그룹 관리** 메뉴에서 사용자와 그룹을 관리합니다. 한 화면에서 왼쪽 그룹 트리로 범위를 고르고, 목록에서 역할을 바로 바꾸고, 여러 명을 선택해 역할 변경·그룹 추가/제외·사용 중지·잠금 해제·강제 로그아웃·삭제를 일괄 처리할 수 있습니다. 사용자 행을 끌어 그룹에 놓으면 구성원으로 추가되고, 그룹을 다른 그룹에 놓으면 하위 그룹이 됩니다(조직 구분용이며 열람 권한은 상속되지 않습니다). 검색은 이름·아이디·이메일·전화·그룹명과 한글 초성(예: `ㅎㄱㄷ`)을 지원합니다. 엑셀에서 표를 복사해 붙여넣거나 CSV(UTF-8/CP949)를 올려 여러 명을 한 번에 등록할 수 있으며, 임시 비밀번호는 자동 생성되어 등록 직후에만 복사·다운로드할 수 있습니다. 역할·그룹·사용 상태 변경은 알림의 **실행 취소**로 되돌릴 수 있습니다. 단축키: `/` 검색, `N` 사용자 추가, `G` 그룹 추가, `Shift+클릭` 범위 선택, `Ctrl+S` 저장, `Esc` 닫기. 자기 계정은 삭제·사용 중지·관리자 해제를 할 수 없고, 마지막 활성 관리자는 항상 유지됩니다. 접속정보는 **리포트 설정 › 접속정보**에서 관리합니다. 양식 생성 또는 양식 관리의 **결과 권한** 탭에서 열람할 그룹과 사용자를 지정할 수 있습니다. 그룹 권한과 사용자 권한은 합산(OR)되며, 어느 하나라도 일치하면 열람할 수 있습니다. 대상을 지정하지 않은 양식과 기본 양식은 모든 사용자가 열람할 수 있습니다. 사용자는 로그인 후 역할에 따라 에디터 또는 뷰어를 선택합니다. 현재는 자체 아이디/비밀번호 로그인만 제공하며, 외부 시스템 자동 로그인(SSO)은 설정만으로 안전하게 사용하도록 연결된 인증 제공자나 신뢰 프록시가 준비되어 있지 않아 제공하지 않습니다.

저장된 사용자 양식은 기본적으로 양식 종류(일간·주간·월간)에 따라 매일·매주 월요일·매월 1일 오전 8시(한국시간)에 실행되며, 양식 관리에서 일정과 시간을 바꿀 수 있습니다. 예약 시각에 서버가 양식의 DB 조회를 다시 실행하고 결과를 붙여 보고서를 `report_documents`에 양식 ID와 실행 날짜별로 저장합니다. 뷰어에서 날짜별로 열람할 수 있고 여러 페이지도 함께 표시됩니다. 예약 시각에 서버가 중단되어 있으면 놓친 실행은 보충하지 않고 다음 예약 시각까지 기다립니다. 컨테이너를 재시작해도 `mariadb_data` 볼륨에 유지됩니다. 기존 `reports` 테이블에 있던 최신 보고서가 있으면 새 테이블로 자동 이전합니다. API는 기본적으로 `127.0.0.1:19080`에만 공개하며, 사내망의 다른 PC에서 접속하려면 `.env`에 `API_BIND_ADDRESS=0.0.0.0`을 설정하고 `docker compose up -d`로 다시 시작한 뒤 `http://<이 PC의 IP>:19080`으로 접속합니다. MariaDB는 로컬 SQL 도구에서 사용할 수 있도록 `127.0.0.1:3307`(또는 `.env`의 `DB_PORT`)에만 공개합니다. 기존 MySQL이 3306을 사용 중이어도 포트 충돌이 나지 않습니다.

## 보고서 메일 전송

관리자는 에디터의 **리포트 설정 → 메일 서버**에서 SMTP 서버 주소, 포트, TLS 또는 STARTTLS, 보내는 사람과 필요 시 인증 정보를 저장하고 연결을 확인합니다. 인증 비밀번호는 `DATASOURCE_SECRET`으로 암호화해 저장하며 다시 표시하지 않습니다. 운영 환경에서는 이 환경변수를 고정하고 안전하게 보관하세요.

에디터의 **보고서 양식 관리 → 메일 전송**에서 주소를 직접 입력하거나 이메일이 등록된 사용자를 선택하고 제목·본문을 저장합니다. 자동 전송을 켜면 해당 양식의 예약 보고서 생성이 성공한 뒤 PDF를 보냅니다. 수동 전송은 뷰어에서 저장된 보고서를 연 뒤 **메일 전송**을 눌러 현재 보고 있는 보고서를 보냅니다. 자동 전송은 보고서 생성 일정이 켜져 있어야 하며, 놓친 일정이나 실패한 메일은 자동 재전송하지 않습니다. 전송 결과는 양식별 최근 이력과 서버 로그에서 확인합니다. SMTP 서버의 수락은 최종 수신을 보장하지 않으며, 일부 수신자 전송 실패 시 재전송 전에 중복 여부를 확인하세요.

PDF 첨부 파일은 뷰어의 결과 열람 권한을 적용할 수 없으므로 받는 사람의 권한과 주소를 확인해야 합니다. 양식에 외부 네트워크 리소스가 포함되어 있으면 안전을 위해 PDF 생성이 실패할 수 있습니다. Docker 이미지에는 PDF 생성에 필요한 Chromium과 한글 글꼴이 포함됩니다. 로컬 실행 시 Chrome 또는 Chromium을 설치하고 필요하면 `CHROME_PATH`에 실행 파일 경로를 지정한 뒤 `npm run build`로 PDF 렌더링 페이지를 빌드하세요. SMTP 서버와 메일 수신 설정을 변경할 권한은 각각 관리자와 에디터 이상에게 있습니다.

뷰어는 한 쪽 보기와 두 쪽 보기 모두 설정된 용지 크기로 보고서를 표시합니다. 화면이 좁으면 가로 스크롤로 확인할 수 있습니다. PDF 내보내기는 보고서 화면을 이미지로 저장하며, 용지 아래로 넘친 내용은 다음 PDF 쪽에 이어집니다. Word·한글 내보내기는 텍스트와 표를 편집 가능한 문서로 다시 구성하므로 문서 프로그램의 글꼴, 줄바꿈, 표 높이와 페이지 나눔에 따라 뷰어와 차이가 날 수 있습니다. 차트·도형과 일부 자유 배치 요소는 그림으로 저장됩니다. 일간 보고서는 화면과 같은 본문 여백을 사용합니다.

유용한 명령:

- `npm run db:seed` — 테스트용 관제 테이블 3개와 예시 데이터 생성/갱신
- `npm run db:logs` — 서버 및 DB 로그 확인
- `npm run db:down` — 컨테이너 중지 (DB 데이터 볼륨은 유지)
- `docker compose down -v` — DB 데이터까지 영구 삭제

## 로컬 개발 서버

Node.js를 설치하고 `npm install`을 실행한 뒤 `.env.example`을 `.env`로 복사하고 DB 접속 정보를 입력합니다. 로컬에 실행 중인 MariaDB를 사용할 경우 `DB_HOST=127.0.0.1`로 설정하고, `npm run dev`를 실행합니다. Vite 개발 주소는 `http://localhost:19080/editor`입니다. Compose로 띄운 DB에 로컬 개발 서버를 직접 연결하려면 Compose DB 포트를 명시적으로 공개하고 `DB_HOST=127.0.0.1`로 설정해야 합니다.

`npm start`는 빌드된 `dist`와 API를 함께 제공합니다. `npm run build`로 먼저 프런트엔드를 빌드하세요. 외부 네트워크에 공개하려면 HTTPS와 방화벽을 구성하고 `.env`에서 `COOKIE_SECURE=true`로 설정하세요. Docker의 기본 계정은 보고서 저장 권한이 있으므로, 이 자격 증명을 외부 데이터베이스에 재사용하지 마세요.

## 데이터 바인딩

### 양식 파일 및 AI 가져오기

에디터 왼쪽 아래에서 현재 양식의 페이지를 JSON으로 내보내거나, 내보낸 JSON을 가져올 수 있습니다(최대 10MB, 50페이지, 1,000개 요소). DB 연결 설정·SQL과 조회 결과는 포함되지 않으며 양식의 공통 머리글·바닥글, 일정 및 권한도 내보내지 않습니다. 가져온 페이지는 현재 양식 뒤에 추가되므로 양식 저장 버튼으로 저장해야 합니다. 아직 저장하지 않은 새 양식이면 새 양식으로 저장합니다.

AI 가져오기는 PDF·PNG·JPG(최대 9MB)를 OpenAI, Anthropic 또는 Google의 선택한 API 모델로 전송해 편집 가능한 텍스트·표·도형·차트를 생성합니다. DOCX와 HWPX는 먼저 PDF로 변환해 주세요. 원본 그림은 자동 삽입되지 않으며 복잡한 서식과 내용은 다를 수 있으므로 결과를 검토하고 수정해야 합니다. 각 제공자의 API 키와 이미지/PDF를 지원하는 유효한 모델이 필요하며, 웹 서비스 계정 로그인과는 별개입니다. 관리자가 에디터의 **리포트 설정 → AI API 키**에서 제공자별 키를 등록하면 모든 에디터가 공유해 사용합니다. 키는 암호화해 저장하고 다시 표시하지 않으며, 설정에서 교체하거나 삭제할 수 있습니다. 양식 가져오기에서 **사용 가능한 모델 불러오기**를 눌러 모델을 선택합니다. Anthropic은 제공자 순서, OpenAI는 생성일 순서로 표시하며, Gemini는 출시일 정보가 없어 모델 ID의 버전순으로 표시합니다. 모델 목록에 포함되어도 문서 분석을 지원하지 않거나 호출 권한이 없을 수 있습니다. 키는 목록 조회와 변환 요청 시 선택한 제공자로 전송됩니다. 파일 전체가 외부에 전송되고 사용 요금이 발생할 수 있으므로 전송 전에 민감정보와 제공자의 데이터 처리 정책을 확인하세요. 외부 공개 환경에서는 HTTPS를 사용하세요.

#### 사내 AI 서버(Ollama)

관리자가 에디터의 **리포트 설정 → 사내 AI**에서 사내 Ollama 주소(예: `http://192.168.0.106:11434`)를 입력하고 연결 확인 후 저장하면, 양식 가져오기의 **사내 AI 서버 (Ollama)**와 에디터의 **AI 어시스턴트**가 이 서버를 사용합니다. API 키가 없고 파일·대화가 외부로 나가지 않으며 사용료가 없습니다. 설정은 `report_ai_settings` 테이블에 저장되며, 한 번도 저장하지 않았으면 `.env`의 `OLLAMA_BASE_URL`을 사용합니다(Docker Compose도 같은 값을 전달). 같은 화면에서 어시스턴트 사용 여부·모델·추론 모드와 문서 분석 기본 모델을 정합니다.

- **모델:** 서버에 설치된 모델 중 비전(이미지 입력)을 지원하는 모델만 표시하며, Qwen 3.5 이상 계열(family `qwen35*`)을 먼저, 그 밖의 Qwen, 기타 비전 모델 순으로 보여 줍니다. `ollama.com` 등으로 요청을 넘기는 원격 모델은 제외합니다. 문서 서식 변환에는 27B 이상 Qwen 비전 모델을 권장합니다.
- **PDF 처리:** Ollama는 PDF를 직접 읽지 못하므로 브라우저에서 pdf.js로 페이지마다 긴 변 1800px PNG로 그린 뒤 한 페이지씩 보냅니다(최대 30페이지, 30MB). 한글 CMap과 표준 글꼴은 빌드 시 `dist/pdfjs/`에 함께 포함됩니다.
- **품질 설정:** 좌표는 Qwen이 익숙한 0~1000 상대 좌표로 받아 595×842 페이지로 환산하고, 요소 종류별 JSON 스키마(`format`)로 출력 형식을 고정합니다. `temperature 0`, `num_ctx 32768`, `num_predict 16384`, `think false`로 요청하며 페이지당 제한 시간은 10분입니다. 형식이 맞지 않는 요소는 페이지 전체를 버리지 않고 해당 요소만 제외한 뒤 개수를 알려 줍니다.
- **취소:** 분석 중 **분석 취소**를 누르면 브라우저 요청과 함께 사내 서버 작업도 중단됩니다.

#### AI 어시스턴트

에디터 상단의 **AI 어시스턴트** 버튼으로 대화창을 열고 말로 요청하면, 사내 AI가 에디터 기능을 도구(tool calling)로 호출해 양식을 직접 편집합니다. 관리자·에디터 역할만 사용할 수 있습니다.

- **할 수 있는 일:** 양식 상태 확인, 요소 추가(여러 개 한 번에)·수정·삭제·이동, 표 셀 편집과 병합·음영·열 너비, 차트 종류·데이터·색 구성, 도형, 페이지 추가·삭제, 용지 크기·방향, 머리글·바닥글·페이지 번호, 데이터소스 조회와 표·차트·텍스트 DB 연결, 양식 열기·새로 만들기·저장(이름·그룹·주기), 양식 삭제(확인 후), 자동 생성 일정, 메일 전송 설정, 미리보기·인쇄. 그림 삽입, 사용자·권한 관리, 서버 설정은 하지 않습니다.
- **구조:** 대화 루프는 브라우저에서 돌고(`src/assistant/`), 서버의 `POST /api/assistant/chat`은 요청 형식을 검증한 뒤 사내 Ollama `/api/chat`의 스트림(NDJSON)을 그대로 중계합니다. 도구는 브라우저의 에디터 상태를 바꾸고 기존 API(양식 저장, 일정, 메일, 쿼리 실행)를 사용자 권한으로 호출하므로 권한 검사는 기존과 같습니다. DB 조회는 기존처럼 SELECT/WITH만 허용됩니다.
- **안전장치:** 요청마다 직전 편집 상태를 보관해 **이 요청 전 상태로 되돌리기**를 제공합니다(서버에 저장된 양식·일정·메일은 제외). 양식 삭제는 대화창의 확인 카드에서 **진행**을 눌러야 실행되며, 한 요청은 최대 16단계까지 진행합니다.
- **모델:** 도구 호출(`tools`)을 지원하는 모델만 쓸 수 있습니다. `qwen3.8:27b`로 시험했을 때 양식 생성 요청이 약 1분 30초, 용지·머리글·저장 같은 설정 요청이 20~40초 걸렸습니다.

운영 환경에서는 DB 비밀번호와 별개의 길고 무작위인 `DATASOURCE_SECRET`을 설정하고 안전하게 보관하세요. 비어 있으면 기존 접속정보와 같이 `DB_PASSWORD`에서 암호화 키를 만듭니다. 기존 설치에서 이 값을 설정하거나 변경하면 기존 DB 접속정보 비밀번호와 AI 키를 다시 등록해야 합니다. 백업 복원 시에도 동일한 암호화 키가 필요합니다.

AI가 감지한 표 셀의 음영은 편집 가능한 셀 배경색으로 반영됩니다. 인식 결과가 원본과 다를 수 있으므로 확인해 주세요.

모델을 선택하면 알려진 모델 계열의 일반적인 특징을 표시하고, Gemini가 모델 설명을 제공하면 원문도 함께 표시합니다. 계열 안내는 해당 모델의 문서 분석 지원 여부나 정확한 가격을 보장하지 않습니다. 상세 기능과 요금은 제공자 문서를 확인하세요.

1. 편집기에서 요소를 선택하고 **데이터 바인딩 → DB 데이터 사용**을 켭니다.
2. `?` 위치 파라미터가 있는 `SELECT`/`WITH` 조회문을 입력합니다. 파라미터는 JSON 배열 순서대로 전달합니다. 예약 실행마다 날짜가 바뀌어야 한다면 아래 날짜 토큰을 사용하세요. 예: 쿼리 `SELECT title FROM reports WHERE report_date = ?`, 파라미터 `["{{reportDate}}"]`.
3. **쿼리 실행 및 필드 불러오기**를 누르고, 각 요소 필드에 연결할 조회 열을 선택합니다. 연결하지 않은 필드는 기존 직접 입력값을 사용합니다.
4. 표는 **제목행 설정**에서 직접 입력할 제목행을 선택합니다. 제목행은 반복되지 않고, DB 데이터는 제목행 아래에 표시됩니다. 바인딩된 표 열은 에디터에서 연결된 필드명만 보이며 실제 조회 데이터는 뷰어에서 확인할 수 있습니다. **조회 결과 행 수만큼 표 행 반복**을 켜면 데이터 건수에 맞춰 행이 늘어납니다.
5. 사용자 양식을 저장한 뒤 **보고서 양식 관리 → 자동 보고서 생성 일정**에서 예약을 켜고 주기·요일/날짜·시간을 지정합니다. 에디터는 날짜별 보고서를 저장하지 않으며, 보고서는 예약 작업만 생성하고 뷰어에서 열람합니다.

예약 쿼리의 JSON 파라미터에서 사용할 수 있는 날짜 토큰:

- `{{reportDate}}` — 실행일
- `{{previousDate}}` — 실행일 전날
- `{{periodStart}}`, `{{periodEnd}}` — 직전 보고 기간의 시작일과 종료일. 매일은 전날, 매주는 직전 월요일~일요일, 매월은 직전 달 1일~말일입니다.

예를 들어 `WHERE report_date = ?`에 `["{{previousDate}}"]`를 지정하면 매일 오전 8시에 전날 통계가 반영됩니다. 주간/월간 쿼리는 `WHERE report_date BETWEEN ? AND ?`와 `["{{periodStart}}", "{{periodEnd}}"]`를 사용합니다.
월간 실행일을 29~31일로 지정하고 해당 월에 그 날짜가 없으면 그 달의 마지막 날에 실행합니다.

### 뷰어에서 즉시 리포트 생성

저장된 보고서를 선택한 뒤 **새 리포트 생성**을 누르고 시작·종료 날짜시간을 지정하면 현재 선택된 양식으로 즉시 생성합니다. 즉시 생성의 DB 바인딩 쿼리는 `WHERE occurred_at BETWEEN ? AND ?`처럼 `?` 두 개를 사용해야 합니다. 저장된 파라미터 값 대신 시작·종료 시각이 자동으로 전달됩니다. 생성본은 기존 보고서를 덮어쓰지 않고 별도 보관하며, 뷰어 목록에서 선택한 시간 범위를 구분해 다시 열 수 있습니다. 시간은 한국시간 기준입니다.

쿼리는 읽기 전용 트랜잭션에서 실행됩니다. 여러 문장·주석·변경/잠금/파일 접근 쿼리는 거부하고, 결과는 최대 5,000행·10초로 제한합니다. 쿼리 필드 이름은 중복되지 않도록 별칭을 지정하세요. 실제 운영 데이터 연결에는 보고서 저장 DB와 분리된 읽기 전용 계정/DB를 사용하세요.

### 테스트용 DB 데이터

DB와 서버를 실행한 다음 `npm run db:seed`를 실행하면 `sample_daily_stats`, `sample_security_events`, `sample_operations_tasks` 테이블에 테스트 데이터가 생성됩니다. 날짜는 `2026-11-06`부터 `2026-11-08`까지이며, 스크립트를 다시 실행해도 데이터가 중복 생성되지 않고 같은 샘플 값으로 갱신됩니다. 이 데이터는 테스트 전용이므로 실제 환자·기관 정보가 아닙니다.

예약 생성 확인용 양식 **Daily 08:00 Generation Test**는 매일 오전 8시(한국시간)에 실행되며 실행 날짜의 `sample_daily_stats`를 표로 연결합니다. `2026-11-08` 보고서는 해당 날짜 샘플 통계로 생성되어 뷰어에서 확인할 수 있습니다.

표 요소의 데이터 바인딩에서 아래 쿼리를 실행하고 파라미터를 `["2026-11-07"]`로 지정해 결과를 확인할 수 있습니다.

```sql
SELECT period_label, monitored_total, detected_total, ignored_closed,
       self_closed, action_required, repeated_detected
FROM sample_daily_stats
WHERE report_date = ?
```

위협 대응 목록:

```sql
SELECT occurred_at, institution_name, threat_type, severity,
       response_status, action_requested_at, action_completed_at, notes
FROM sample_security_events
WHERE report_date = ?
ORDER BY occurred_at
```

업무 항목 목록:

```sql
SELECT section_name, task_title, task_status, owner_name, details, next_action
FROM sample_operations_tasks
WHERE report_date = ?
ORDER BY task_id
```

## API 및 접근 경로

- `/` — 에디터/뷰어 진입
- `/editor` — 보고서 양식 편집·저장 및 자동 실행 일정 설정
- `/viewer` — 예약 생성된 보고서를 선택해 열람 및 인쇄
- `/admin` — 사용자·그룹 관리 (관리자 전용)
- `GET/POST /api/admin/users`, `PATCH/DELETE /api/admin/users/:userCd` — 사용자 조회·추가·부분 수정(이름·이메일·전화·역할·상태·비밀번호·잠금 해제·소속 그룹)·삭제
- `POST /api/admin/users/bulk` — 일괄 작업(`setRole`, `enable`, `disable`, `unlock`, `addToGroup`, `removeFromGroup`, `logout`, `delete`)
- `POST /api/admin/users/import` — 최대 500명 일괄 등록(없는 그룹 자동 생성 선택)
- `GET/POST /api/admin/groups`, `PATCH/DELETE /api/admin/groups/:groupCd`, `PUT /api/admin/groups/:groupCd/members` — 그룹·상위 그룹·구성원 관리 (삭제 시 하위 그룹은 한 단계 위로 이동)
- 뷰어의 **새 리포트 생성** — 선택 양식과 시작·종료 날짜시간으로 즉시 생성하며, 기존 저장본은 보존
- 뷰어 보고서 선택은 양식별 저장 날짜로 그룹화되며, 여러 페이지 보고서를 한 페이지 또는 두 페이지씩 표시할 수 있습니다.
- `GET /api/reports?type=daily` — 저장된 보고서 목록
- `GET /api/reports/:type/:date`, `PUT /api/reports` — 유형·날짜별 조회 및 저장
- `POST /api/reports/generate`, `GET /api/reports/instances/:id` — 시간 범위로 새 보고서를 생성하고 개별 생성본 조회
- `GET /api/templates`, `POST /api/templates`, `PUT /api/templates/:id` — 사용자 양식 조회·생성·수정
- `GET /api/schedules`, `PUT /api/schedules/:type` — 양식별 자동 생성 일정 조회·저장
- `GET /api/reports/latest`, `PUT /api/reports/latest` — 이전 클라이언트 호환용 최신 보고서 API
- `GET /api/data/status`, `POST /api/data/query` — DB 설정 확인/조회 실행

샘플 보고서는 `public/reports/daily-report.json`에 있습니다. 인쇄 시 배경색을 보존하려면 브라우저 인쇄 설정에서 **배경 그래픽**을 켜고 **머리글 및 바닥글**을 끄세요.
